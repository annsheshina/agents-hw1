## 1. Задача и подход

Цель работы — создать две версии мини-трекера учебных задач
и сравнить два способа разработки с помощью ИИ.

Первая версия, tracker-v1.html, создавалась по короткому
прямому запросу.

Вторая версия, tracker-v2.html, создавалась после подготовки
и просмотра четырёх документов:

- proposal.md — цель и границы;
- specs/tracker/spec.md — требования и сценарии;
- design.md — структура данных и расчёты;
- tasks.md — план реализации и проверок.

Для второй попытки использована спецификация в формате
OpenSpec, без запуска OpenSpec CLI.

Попытки выполнялись в отдельных чатах.
Код первой версии не передавался во вторую попытку.

## 2. Условия и учёт работы

Сервис генерации: Perplexity.
Конкретная модель и её версия не зафиксированы.
Поэтому использование одной и той же модели в двух попытках
не подтверждено. Это ограничение сравнения.

В сохранённом prompts.txt содержатся:
- первая попытка — один основной запрос на реализацию;
- вторая попытка — два основных запроса: подготовка
  документов и реализация.

Эти числа отражают сохранённые запросы, а не независимо
проверенный полный журнал всех обращений.

Точное время работы над каждой попыткой не фиксировалось.
Токены и стоимость: нет данных.

Ручная проверка проводилась на macOS в браузере Safari.
Для сохранения файлов использовался TextEdit
в режиме обычного текста.

## 3. Исходные данные и ожидаемое поведение

Модель задачи:
- id — уникальный идентификатор;
- title — название;
- hours — оценка в часах;
- done — отметка готовности.

Исходные задачи:
- «Чтение» — 2 ч, готово;
- «Практика» — 4 ч, активно;
- «Повторение» — 2 ч, активно.

Исходные показатели:
- всего 8 ч;
- выполнено 2 ч;
- прогресс 25%.

Прогресс должен рассчитываться по часам, а не по количеству
задач. После отметки «Практики» готовой ожидается
6 выполненных часов из 8 и прогресс 75%.

Фильтры должны менять только видимый список, не влияя
на общие показатели.

## 4. Запуск

Для запуска первой версии нужно открыть файл:

attempt-1-direct/tracker-v1.html

Для запуска второй версии нужно открыть файл:

attempt-2-spec/tracker-v2.html

Файлы открываются непосредственно в браузере.
Установка библиотек и запуск сервера не требуются.

Во второй версии сохранение в localStorage
не запрашивалось: достаточно работы в памяти.

## 5. Результаты проверки tracker-v1

### T1 — Исходный пример

Действие: открыть исходные три задачи.

Ожидание: 3 задачи; всего 8 ч; выполнено 2 ч;
прогресс 25%.

Факт: 3 задачи; всего 8 ч; выполнено 2 ч;
прогресс 25%.

Статус: пройдено.

### T2 — Переключение готовности

Действие: отметить «Практику» готовой.

Ожидание: выполнено 6 из 8 ч; прогресс 75%.

Факт: «Практика» отмечена готовой;
выполнено 6 из 8 ч; прогресс 75%.

Статус: пройдено.

### T3 — Фильтр

Действие: вернуть исходные статусы и включить
фильтр «активные».

Ожидание: видны только «Практика» и «Повторение»;
всего 8 ч; выполнено 2 ч; прогресс 25%.

Факт: видны «Практика» и «Повторение»;
«Чтение» скрыто. Всего 8 ч; выполнено 2 ч;
прогресс 25%. Фильтр не меняет показатели.

Статус: пройдено.

### T4 — Валидация

Ожидание: некорректная задача не добавляется;
ошибка отображается рядом с полем;
введённые значения сохраняются для исправления.
Часы допустимы от 0,5 до 24 включительно с шагом 0,5.

Зафиксированные результаты:
1. Пустое название — задача не добавлена,
   показано сообщение об ошибке.
2. Название из пробелов — задача не добавлена,
   показано сообщение об ошибке.
3. Пустые часы — задача не добавлена,
   показано сообщение об ошибке.
4. Часы −3 — задача не добавлена,
   показано сообщение об ошибке.
5. Часы 0 — задача не добавлена,
   показано сообщение об ошибке.

Для этих пяти случаев проверка пройдена.

Дополнительные случаи, результаты которых не зафиксированы:
- успешное добавление с 0,5 и 24 ч;
- отклонение 24,5 и 0,75 ч;
- расположение ошибки именно рядом с полем;
- сохранение введённых значений при ошибке.

Статус T4 в целом: частично проверено.

### T5 — Пустое состояние

Действие: удалить все задачи.

Ожидание: всего 0 ч; прогресс 0%;
нет NaN или Infinity; интерфейс продолжает работать.

Факт: все задачи удалены; отображается 0 ч и 0%;
NaN и Infinity нет; интерфейс работает.

Статус: пройдено по зафиксированным наблюдениям.

Отдельный результат повторного добавления задачи
после удаления всех задач не зафиксирован.

## 8. Проблема с сохранением второй версии

При первом открытии сохранённого tracker-v2.html
в Safari отображалась пустая страница с фоном.

При просмотре сохранённого файла обнаружено,
что код обрывается посреди CSS на строке:

border: 1px

В файле отсутствовала оставшаяся часть приложения.

После сохранения полного кода страница стала
открываться и показывать интерфейс.

Изменение «до → после»:
- до: неполный файл, пустая страница с фоном;
- после: сохранён полный код, интерфейс отображается.

По имеющимся данным нельзя установить, был ли
обрезан ответ модели или при копировании была
сохранена только его часть.

Это не подтверждённая ошибка логики трекера.
Другие исправления в данном отчёте не описаны.

## 9. Сравнение и вывод

Первая попытка начиналась с короткого запроса,
после которого модель сразу создавала код.

Во второй попытке сначала были подготовлены
цель, требования, дизайн и план проверок,
а реализация запрашивалась отдельным сообщением.

Для первой версии зафиксированы успешные результаты
T1, T2, T3 и основных наблюдений T5.
В T4 успешно проверены пять некорректных вариантов,
но дополнительные требования проверены не полностью.

Для второй версии подтверждено открытие интерфейса
после сохранения полного файла. Отдельные результаты
T1–T5 в отчёте не зафиксированы.

Поэтому на основании этого отчёта нельзя утверждать,
что вторая версия лучше первой или что обе версии
прошли одинаковые проверки.

Подготовка спецификации сделала требования явными
и сформировала план реализации и приёмки.
Однако наличие документов не заменяет фактическую
проверку приложения.

## 10. Ограничения

- Выполнена одна попытка для каждого подхода.
- Конкретная модель не зафиксирована, поэтому
  одинаковость модели в двух попытках не подтверждена.
- Во второй попытке запрос подробнее и содержит
  отдельный этап подготовки документов.
- Точное время, токены и стоимость не измерены.
- Полнота журнала обращений отдельно не подтверждена.
- Результаты функциональных проверок второй версии
  требуют фиксации.
- Работа на ширине 390 px отдельно не подтверждена.
- Незафиксированные проверки не считаются успешными.
