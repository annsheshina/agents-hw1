# Спецификация мини-трекера учебных задач

## ADDED Requirements

### Requirement: Автономная поставка

Приложение MUST представлять собой автономный мини-трекер учебных задач
на неделю в одном файле `tracker-v2.html`.

CSS и JavaScript MUST находиться внутри файла.
Приложение MUST работать без сервера, CDN, внешних библиотек и API-ключей.

#### Scenario: Открытие файла
- WHEN пользователь открывает `tracker-v2.html` в браузере
- THEN обязательные функции доступны без сервера и внешних зависимостей.

### Requirement: Модель задачи и исходные данные

Каждая задача MUST содержать поля `id`, `title`, `hours`, `done`.
Поле `id` MUST однозначно идентифицировать задачу.

Исходный пример MUST содержать:
- «Чтение»: `hours=2`, `done=true`;
- «Практика»: `hours=4`, `done=false`;
- «Повторение»: `hours=2`, `done=false`.

#### Scenario: Исходный пример — T1
- WHEN загружены исходные данные
- THEN в коллекции находятся три указанные задачи
- THEN всего запланировано 8 ч
- THEN выполнено 2 ч
- THEN прогресс равен 25%.

### Requirement: Добавление задачи

Добавление корректной задачи MUST изменять коллекцию данных.
Новая задача MUST получать уникальный `id` и `done=false`.

Название после `trim` MUST быть непустым.
Название MUST сохраняться после `trim`.

Часы MUST быть конечным числом в диапазоне от 0,5 до 24 включительно
с шагом 0,5.
Пустое значение часов MUST отклоняться отдельно и MUST NOT трактоваться
как числовой ноль.

При некорректном вводе приложение MUST:
- не добавлять задачу;
- показывать ошибку рядом с соответствующим полем;
- сохранять введённые значения формы.

#### Scenario: Корректное добавление
- WHEN введены непустое после `trim` название и допустимые часы
- THEN новая задача добавляется в данные с `done=false`
- THEN список и общие показатели обновляются.

#### Scenario: Пустое название — T4
- WHEN пользователь отправляет форму с пустым названием
- THEN задача не добавляется
- THEN рядом с полем названия видна ошибка
- THEN введённые значения формы сохраняются.

#### Scenario: Название из пробелов — T4
- WHEN пользователь отправляет форму с названием только из пробелов
- THEN задача не добавляется
- THEN рядом с полем названия видна ошибка
- THEN введённые значения формы сохраняются.

#### Scenario: Пустые часы — T4
- WHEN пользователь отправляет форму с пустыми часами
- THEN задача не добавляется
- THEN рядом с полем часов видна ошибка
- THEN введённые значения формы сохраняются.

#### Scenario: Отрицательные часы — T4
- WHEN пользователь отправляет форму с отрицательными часами
- THEN задача не добавляется
- THEN рядом с полем часов видна ошибка
- THEN введённые значения формы сохраняются.

#### Scenario: Допустимые границы и шаг — T4
- WHEN при корректном названии по отдельности введены 0,5 ч, 24 ч
  или допустимое промежуточное значение с шагом 0,5
- THEN задача может быть добавлена.

#### Scenario: Недопустимый диапазон, шаг или тип — T4
- WHEN часы меньше 0,5, больше 24, не соответствуют шагу 0,5
  или не являются конечным числом
- THEN задача не добавляется
- THEN рядом с полем часов видна ошибка
- THEN введённые значения формы сохраняются.

### Requirement: Переключение готовности

Переключение готовности MUST изменять поле `done` выбранной задачи
в коллекции данных, а не только её внешний вид.

После изменения MUST обновляться видимый список и общие показатели.

#### Scenario: Завершение «Практики» — T2
- WHEN в исходном примере «Практика» отмечена готовой
- THEN её `done` равно `true`
- THEN выполнено 6 из 8 ч
- THEN прогресс равен 75%.

#### Scenario: Возврат задачи в активные
- WHEN пользователь снимает готовность выполненной задачи
- THEN её `done` равно `false`
- THEN список и общие показатели пересчитываются.

### Requirement: Удаление задач

Удаление MUST удалять выбранную задачу из коллекции данных,
а не только скрывать её.

После удаления MUST обновляться видимый список и общие показатели.

#### Scenario: Удаление отдельной задачи
- WHEN пользователь удаляет задачу
- THEN задача отсутствует в коллекции
- THEN её часы больше не участвуют в расчётах.

#### Scenario: Удаление всех задач — T5
- WHEN все задачи удалены
- THEN коллекция и видимый список пусты
- THEN всего 0 ч и выполнено 0 ч
- THEN прогресс равен 0%
- THEN отсутствуют `NaN` и `Infinity`
- THEN интерфейс продолжает работать.

### Requirement: Расчёт часов и прогресса

Общее время MUST равняться сумме часов всех задач.
Выполненное время MUST равняться сумме часов задач с `done=true`.

Прогресс MUST вычисляться как округление до целого:
`100 × сумма часов done / сумма часов всех задач`.

Если задач нет, прогресс MUST равняться 0% без деления на ноль,
`NaN` или `Infinity`.

#### Scenario: Прогресс взвешен по часам
- WHEN в исходном примере выполнено только «Чтение»
- THEN прогресс равен 25%, поскольку выполнено 2 из 8 ч.

#### Scenario: Пустая коллекция
- WHEN коллекция не содержит задач
- THEN общее и выполненное время равны 0 ч
- THEN прогресс равен 0%.

### Requirement: Фильтрация

Приложение MUST предоставлять фильтры «все», «активные», «готовые».

Фильтр MUST влиять только на видимый список.
Фильтр MUST NOT изменять коллекцию задач.
Итоговые часы и прогресс MUST рассчитываться по всем задачам независимо
от выбранного фильтра.

#### Scenario: Активные задачи — T3
- WHEN восстановлен исходный пример и включён фильтр «активные»
- THEN видны только «Практика» и «Повторение»
- THEN всего остаётся 8 ч
- THEN выполнено 2 ч
- THEN прогресс остаётся 25%.

#### Scenario: Готовые задачи
- WHEN в исходном примере включён фильтр «готовые»
- THEN видно только «Чтение»
- THEN общие показатели остаются 8 ч, 2 ч и 25%.

#### Scenario: Все задачи
- WHEN включён фильтр «все»
- THEN видны все задачи текущей коллекции.

#### Scenario: Пустой результат фильтра
- WHEN выбранному фильтру не соответствует ни одна задача
- THEN видимый список пуст
- THEN показатели продолжают рассчитываться по полной коллекции.

### Requirement: Читаемый интерфейс

Интерфейс MUST быть читаемым при ширине области просмотра 390 px
без горизонтального скролла.

Поля и кнопки MUST иметь понятные подписи.
Ошибки MUST отображаться рядом с соответствующими полями.

#### Scenario: Узкий экран
- WHEN ширина области просмотра составляет 390 px
- THEN поля, кнопки, список, ошибки и показатели читаемы
- THEN горизонтальный скролл отсутствует.

### Requirement: Необязательное сохранение в localStorage

Сохранение в `localStorage` является необязательным улучшением.
Требования этого раздела применяются только при его реализации.

При реализованном улучшении приложение MUST сохранять задачи
после изменения и восстанавливать их при следующем открытии,
если хранилище доступно.

При недоступном хранилище приложение MUST показывать понятное сообщение
и MUST продолжать работать в памяти.

Ограничение MUST быть описано: при открытии через `file://`
поведение `localStorage` зависит от браузера.

#### Scenario: Восстановление сохранённых задач
- WHEN приложение открывается повторно и сохранённые задачи доступны
- THEN восстанавливается сохранённая коллекция.

#### Scenario: Сохранённый пустой список
- WHEN ранее были удалены все задачи и пустая коллекция сохранена
- THEN при повторном открытии восстанавливается пустая коллекция
- THEN она не заменяется исходным примером.

#### Scenario: Недоступное хранилище
- WHEN чтение или запись в хранилище недоступны
- THEN пользователь видит понятное сообщение
- THEN добавление, удаление, переключение готовности и расчёты
  продолжают работать в памяти.

### Requirement: Независимые проверки и разделение этапов

Перед независимыми сценариями MUST восстанавливаться исходные данные.
Отдельная кнопка сброса не обязательна.

Подготовка документов и реализация MUST выполняться разными запросами.
На этапе спецификации код HTML MUST NOT создаваться.

Фактически проведённые проверки MUST перечисляться отдельно
от предложенных.
Задачи MUST NOT отмечаться выполненными до фактического выполнения.
Запуск OpenSpec CLI, валидатора или браузера MUST NOT заявляться,
если его не было.

#### Scenario: Подготовка независимого сценария
- WHEN начинается независимая проверка T1–T5
- THEN предварительно восстановлены исходные данные
- THEN установлены условия соответствующего сценария.

#### Scenario: Текущий этап документов
- WHEN подготовлены спецификация, дизайн и план работ
- THEN реализация и проверки остаются невыполненными
- THEN отсутствуют заявления о запуске CLI, валидатора или браузера.
