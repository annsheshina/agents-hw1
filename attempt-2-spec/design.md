# Дизайн мини-трекера

## 1. Поставка и границы

Результат будущей реализации — один автономный файл `tracker-v2.html`
со встроенными CSS и JavaScript.

Сервер, CDN, внешние библиотеки и API-ключи не используются.
Трекер предназначен для учебных задач на неделю.
Дополнительные функции сверх исходной постановки не предусматриваются.

Этот документ описывает решение; HTML-код на текущем этапе не создаётся.

## 2. Структура данных

Основное состояние — коллекция задач.

| Поле | Тип | Правило |
|---|---|---|
| id | строка | Уникальный идентификатор |
| title | строка | Непустая после trim; хранится после trim |
| hours | число | Конечное, от 0,5 до 24 включительно, шаг 0,5 |
| done | логическое | true — готовая задача, false — активная |

Исходная коллекция:

| id | title | hours | done |
|---|---|---:|---|
| task-1 | Чтение | 2 | true |
| task-2 | Практика | 4 | false |
| task-3 | Повторение | 2 | false |

Идентификаторы новых задач не должны совпадать с существующими.

## 3. Состояние интерфейса

Отдельно от коллекции задач находятся:
- текущий фильтр: «все», «активные» или «готовые»;
- введённое значение названия;
- введённое значение часов;
- ошибки полей;
- сообщение о недоступности хранилища, если сохранение реализовано.

Значения формы сохраняются в исходном виде до успешной проверки.
В частности, пустая строка часов не заменяется нулём.

При ошибке форма не очищается и не заменяется нормализованными значениями.
Обрезанное название записывается в задачу только при успешном добавлении.

## 4. Изменение данных

### Добавление

1. Прочитать значения формы.
2. Проверить название и часы.
3. При ошибках показать сообщения рядом с полями, не менять коллекцию
   и сохранить введённые значения.
4. При успехе добавить задачу с уникальным `id`, названием после `trim`,
   числовыми часами и `done=false`.
5. Обновить список и показатели.

### Переключение готовности

1. Найти задачу по `id`.
2. Изменить `done` на противоположное значение.
3. Обновить список с учётом текущего фильтра и пересчитать показатели.

### Удаление

1. Найти задачу по `id`.
2. Удалить её из коллекции.
3. Обновить список и показатели.

Все операции меняют основную коллекцию, а не только отображение.

## 5. Валидация

### Название

- Применить `trim`.
- Отклонить пустой результат, включая ввод только из пробелов.
- При успешном добавлении сохранить результат `trim`.

### Часы

Проверки выполняются в следующем порядке:
1. Отдельно отклонить пустой ввод.
2. Проверить, что ввод задаёт конечное число.
3. Проверить диапазон: от 0,5 до 24 включительно.
4. Проверить шаг 0,5: удвоенное значение часов должно быть целым.

Допустимые примеры: 0,5; 1; 1,5; 24.
Недопустимые примеры: пустое значение; отрицательное число; 0; 0,25;
0,75; 24,5; нечисловое или неконечное значение.

Десятичные значения в документации записаны через запятую.
В модели `hours` хранится как число, а не как форматированная строка.

### Ошибки

Ошибки показываются рядом с соответствующими полями.
Если некорректны оба поля, показываются ошибки обоих полей.
Неуспешная проверка не добавляет задачу и сохраняет все значения формы.

## 6. Расчёты

Показатели выводятся из полной коллекции задач:

- H — сумма `hours` всех задач;
- D — сумма `hours` задач с `done=true`;
- P — округлённый до целого процент прогресса.

Правила:
- общее время = H;
- выполненное время = D;
- если задач нет, P = 0;
- иначе P = округление `100 × D / H` до ближайшего целого.

Пустая коллекция обрабатывается до деления.
У непустой корректной коллекции H положительно, поскольку каждая задача
содержит не менее 0,5 ч.

Контрольные значения:

| Состояние | Всего | Выполнено | Прогресс |
|---|---:|---:|---:|
| Исходный пример | 8 ч | 2 ч | 25% |
| «Практика» отмечена готовой | 8 ч | 6 ч | 75% |
| Исходный пример, фильтр «активные» | 8 ч | 2 ч | 25% |
| Все задачи удалены | 0 ч | 0 ч | 0% |

Прогресс зависит от часов, а не от количества задач.

## 7. Фильтрация

Видимый список формируется из основной коллекции:
- «все»: вся коллекция;
- «активные»: только задачи с `done=false`;
- «готовые»: только задачи с `done=true`.

Фильтрация не изменяет данные и не участвует в расчёте H, D и P.

После переключения готовности задача может исчезнуть из текущего
отфильтрованного списка. Это не означает её удаления.

В исходном примере:
- «активные» показывает «Практику» и «Повторение»;
- «готовые» показывает «Чтение»;
- оба фильтра сохраняют показатели 8 ч, 2 ч и 25%.

## 8. Пустое состояние

Нужно различать два состояния:

1. Коллекция пуста:
   - в списке нет задач;
   - всего 0 ч;
   - выполнено 0 ч;
   - прогресс 0%;
   - отсутствуют `NaN` и `Infinity`;
   - форма и остальные элементы продолжают работать.

2. Коллекция непуста, но фильтр ничего не показывает:
   - видимый список пуст;
   - задачи остаются в данных;
   - показатели рассчитываются по полной коллекции, а не обнуляются.

## 9. Интерфейс

Состав интерфейса:
- подписанные поля названия и часов;
- кнопка добавления;
- ошибки рядом с полями;
- фильтры «все», «активные», «готовые»;
- список с названием, часами, переключением готовности и удалением;
- общее время, выполненное время и прогресс.

Компоновка и перенос содержимого должны обеспечивать читаемость
при ширине области просмотра 390 px без горизонтального скролла.
Поля и кнопки имеют понятные подписи.

## 10. Необязательное сохранение

Обязательная версия может хранить задачи только в памяти.

Если выбрано улучшение с `localStorage`:
- при отсутствии сохранённых данных используется исходный пример;
- сохранённая коллекция восстанавливается при открытии;
- пустая сохранённая коллекция не заменяется исходным примером;
- после добавления, удаления и переключения готовности коллекция сохраняется;
- недоступность чтения или записи обрабатывается без остановки приложения;
- показывается понятное сообщение, работа продолжается в памяти.

Сохранение фильтра и содержимого формы не требуется.

Ограничение для описания пользователю:
«При открытии через file:// поведение localStorage зависит от браузера.
Если хранилище недоступно, трекер продолжает работать в памяти,
но изменения не сохраняются между открытиями».

## 11. Подготовка проверок

Перед независимыми сценариями восстанавливается исходная коллекция.
Отдельная кнопка сброса не требуется.

Без сохранения исходные данные можно восстановить повторным открытием
страницы. При включённом сохранении необходимо предварительно удалить
или заменить сохранённые тестовые данные.

Проверки, предложенные в `tasks.md`, не считаются выполненными.
