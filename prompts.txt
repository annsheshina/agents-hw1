ПОСТАНОВКА

Результат: автономный мини-трекер учебных задач на неделю — один файл tracker-v2.html с CSS и JavaScript внутри, без сервера, CDN, внешних библиотек и API-ключей.

Данные задачи: id, title, hours, done.

Стартовый пример:
- «Чтение» — 2 ч, done=true;
- «Практика» — 4 ч, done=false;
- «Повторение» — 2 ч, done=false.

Требования:
1. Добавление, удаление и переключение done реально меняют данные.
2. Название после trim непустое. Часы — число 0,5–24 с шагом 0,5. Пустое значение не равно нулю. Ошибка видна рядом с полем, данные формы сохраняются.
3. Прогресс = округление(100 × сумма часов done / сумма часов всех задач). Если задач нет — 0%, без NaN/Infinity.
4. Фильтр «все / активные / готовые» влияет только на видимый список. Итоговые часы и прогресс считаются по всем задачам.
5. При старте примера всего 8 ч, выполнено 2 ч, прогресс 25%. Если отметить «Практику» готовой — 6/8 и 75%.
6. Интерфейс читаем на ширине 390 px, без горизонтального скролла. Поля и кнопки подписаны.

Приёмка WHEN/THEN:
- WHEN включён фильтр «активные», THEN список меняется, прогресс остаётся 25%.
- WHEN введено пустое название или пустые/отрицательные часы, THEN задача не добавляется и видна ошибка.
- WHEN все задачи удалены, THEN итог 0 ч и прогресс 0%.
- WHEN «Практика» отмечена готовой, THEN прогресс 75%.

Необязательное улучшение: сохранять задачи в localStorage, а при недоступном хранилище показывать понятное сообщение и продолжать работу в памяти. При открытии через file:// поведение localStorage зависит от браузера; ограничение нужно описать.

Общие проверки T1–T5:
T1 — исходные 3 задачи: всего 8 ч, выполнено 2 ч, прогресс 25%.
T2 — отметить «Практику» готовой: выполнено 6 из 8 ч, прогресс 75%.
T3 — вернуть исходные данные и включить фильтр «активные»: видны «Практика» и «Повторение», общий прогресс остаётся 25%.
T4 — по отдельности проверить пустое название, пробелы, пустые и отрицательные часы; дополнительно границы 0,5–24 и шаг 0,5. Некорректная задача не добавляется, видна ошибка, введённые значения сохраняются.
T5 — удалить все задачи: итог 0 ч и 0%, нет NaN или Infinity, интерфейс продолжает работать.

Перед независимыми сценариями нужно восстанавливать исходные данные; отдельная кнопка сброса не обязательна.

Документы и реализация выполняются разными запросами. При подготовке спецификации код не писать. Фактически проведённые проверки перечислять отдельно от предложенных; запуск браузера не заявлять, если его не было.
